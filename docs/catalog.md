# Indicator catalog and political records

One Workflow, `CatalogWorkflow`, builds the indicator catalog and stores the political records. Searches and charts only read what it stored.

## Indicator catalog

Indicator search reads a catalog of World Bank indicators, Eurostat datasets and OECD dataflows, kept in D1 for search by words and in Vectorize for search by meaning. Searches only read it. The `CatalogWorkflow` Workflow (`packages/server/src/CatalogBuild.ts`) builds it every Monday at 04:00 UTC from a native Workflow schedule, and CI starts one more build after each deploy, through the Workflows API.

One build changes the catalog at a time. A build first takes a lease, a row in `catalog_lease` naming its Workflow instance, and releases it when it ends, failed or not. A build that finds the lease held sleeps 10 minutes and asks again, so the build a deploy started still runs that deploy's code after the earlier build ends. The lease expires after 12 hours, which frees it from a build that crashed without releasing it; a first build of every source makes about 110 embedding and 214 classifying steps, and a step that keeps failing gives up after about an hour. Without the lease, CI's build after a deploy could overlap the weekly one or an earlier deploy's, and the older build would remove the vectors of entries the newer one had embedded but not yet published. A build that takes the lease after a newer one published a source leaves that source alone.

A build lists each source in one request, writes its entries into a new generation, embeds its new and changed entries 100 at a time, publishes the generation, which drops the source's older ones, then removes the vectors of the entries it dropped. Each of those is a Workflow step: a failed step retries alone, for about half an hour, and a resumed build skips the steps that completed. Sources build side by side, so one that stays down keeps its previous generation while the others publish. A stage answers "unavailable" to a search of every source until a build publishes one of them, and to a search of one source until a build publishes that source, so a source that has never built does not answer that it lists no such indicator. Eurostat's list carries names only: its full list with descriptions is 20 MB. The World Bank's list is the World Development Indicators, which republish the estimate and 0 to 100 score of the six Worldwide Governance Indicators (`GOV_WGI_*`) and leave out their standard errors and confidence bounds; their charts credit the Worldwide Governance Indicators.

The write step first compares a fingerprint of the listing with the one stored beside the source's published generation (`catalog_fingerprint`). The fingerprint is a SHA-256 of the sorted entries and the embedding model, so a deploy that changes either rebuilds the source. When they match, the step writes nothing and the source stops there, keeping its published generation. The step saves that decision, so a resumed build makes the same one. A build where no source changed makes one listing request per source, eight steps (a write and a classify per source, and taking and releasing the lease), and no Workers AI or OpenAI calls. A new stage, or one whose generations predate fingerprints, builds everything once.

When a source did change, `catalog_vector` decides what to embed. It records, for each vector in Vectorize, the entry's name and definition and the model that embedded it, written after each upsert. An embed step takes the generation's next 100 entries that differ from that record, embeds them in one Workers AI call and one Vectorize upsert, and saves the last row it embedded as its cursor. Entries whose name and definition did not change keep their vectors, and a change of embedding model differs from every record, so it embeds everything again. After publishing, a remove step deletes the vectors of up to 100 recorded entries that neither the published generation nor a newer one lists, and saves how many it deleted. A build where one World Bank entry was renamed makes one Workers AI call for 1 entry and one Vectorize upsert, where it used to embed every World Bank entry; a dropped entry adds one Vectorize delete.

Each step reads its decision from D1 and saves only a cursor or a count, so a resumed build embeds and removes the same entries as one that did not stop, even when the Worker stopped after a step ran but before Workflows saved it. Vectors change before the generation that needs them is published, as before; until a removal runs, search by meaning drops neighbors the published generation does not list. A stage whose tables predate `catalog_vector` gets the table on its next build and embeds each changed source in full once.

Every build then classifies which way each entry's values are better: Higher, Lower or Neutral, which colours maps and change charts green to red (`packages/server/src/ModelClassifier.ts`). It runs for every source that listed, changed or not, over the published generation. `catalog_direction` records, for each indicator, the direction and the name and definition the model read; it is kept across generations. A classify step takes the next 50 entries whose name and definition differ from that record, asks the agent's OpenAI model about them in one request, stores the answers and saves the last row it asked about as its cursor. The model reads each entry's name and its definition cut to 400 characters; the catalog stores no unit apart from what the name says. An answer outside the three directions, or an entry the model leaves out, is stored as Neutral. A request that fails stores nothing and ends the source's classification for that build, which still succeeds; the next build asks again. A stage without an OpenAI key classifies nothing. A build where nothing changed asks the model nothing.

A chart reads its indicator's direction from the hand-checked list in `packages/server/src/Directions.ts` first, then from `catalog_direction`, else Neutral. A first pass over the whole catalog, measured on a sample of 100 entries per source, is about 214 requests, 690,000 input and 310,000 output tokens.

## Political records

Trend charts can mark each country's national elections and shade who governed it, for the EU and OECD members. The same `CatalogWorkflow` run stores elections and governments in D1 (`packages/server/src/PoliticsBuild.ts`), one generation per publisher and kind like the catalog, and `GET /api/politics?countries=ESP,PRT&from=2000&to=2020` reads them (`packages/server/src/Politics.ts`). The publishers, what each records and their licences are in the README's [sources table](../README.md#sources-and-licences).

PPEG counts within its coverage, ParlGov fills the years before it, and records checked by hand follow both. PPEG and ParlGov can date the same election differently (France's first or second round), so they are never added together. The sources record when a government starts, never when it ends: it ends when the next starts. No winner or coalition is inferred from an election. European Parliament elections are left out. The chart credits PPEG and ParlGov with the citations they ask for.

The same route answers major events and pension reforms from a snapshot checked in beside the official pages (`events.json`, `reforms.json`, ported from countries-comparison; see `packages/server/src/official/README.md`). Every record cites at least one https page, which the card's source line links. An event shows on a country's chart only if it concerns that country, and a reform only on a chart of its policy area: `areas` in `packages/domain/src/Politics.ts` lists the Eurostat and OECD indicators of each. No build stores them, but the route still answers "unavailable" until builds have published the elections and the governments of every publisher. Every answer reads all six, so one missing would show a country as having no government records when they are only not stored yet.

Like the catalog's, the write step skips a publisher's records of one kind when their fingerprint matches the published generation's (`politics_fingerprint`). The fingerprint leaves out when the build fetched them, which changes every build, so skipped records keep the retrieval time of the build that stored them. A build where nothing changed makes six steps.

## Rebuild by hand

To rebuild a deployed stage, start an instance from the Cloudflare dashboard (Workers & Pages, Workflows, `civicdata-<stage>-catalog`) or with `POST /accounts/<account>/workflows/civicdata-<stage>-catalog/instances`.
